## The whole statement, in the form a vetting form wants

| Question a district asks | Answer |
|---|---|
| Does the tool require student accounts, sign-in, or SSO? | **No.** There is no sign-in of any kind, which also takes it out of the Google Workspace for Education under-18 third-party-app block [PRODUCT.md §6.2; support.google.com/a/answer/13288950]. |
| What student data does it collect? | **None.** No names, no text, no keystrokes, no grades, no device identifiers. There is no server to send anything to: the site is static files. |
| Where does the student's typed sentence go? | **Nowhere.** It is tokenized and run through the model inside the browser tab. No network request carries it. |
| Cookies, analytics, tracking pixels, fingerprinting? | **None.** No cookie, no beacon, no self-hosted counter, no third-party script [PRODUCT.md §8.3 "Web analytics: none"]. |
| Does it call any AI service (OpenAI, Google, etc.)? | **No.** The model is a 7.5 MB file downloaded from the lesson site itself and executed by the page's own JavaScript. There is no AI-chat traffic signature for a filter to detect [PRODUCT.md §6.2]. |
| What is stored on the device? | Only ordinary browser cache: the page, its script, the ~2 MB tokenizer files and the 7.5 MB model file, so the second visit is fast. One preference value (the EN/中文 language choice) is kept in the browser's local storage. Nothing a student types is stored anywhere, including locally. Clearing site data removes all of it. |
| Does it work offline? | After the first load it keeps working if the connection drops. Surviving a page *reload* offline requires the classroom build's service worker (planned; PRODUCT.md §6.1). |
| Who operates it? | A single author, with no company, no revenue, no advertising, no sponsors, no donations [PRODUCT.md "Non-negotiable constraints"]. |
| Age range | Designed for grades 9–14. No student data is collected at any age, so the grade label exists for developmental fit and state policy, not for privacy [PRODUCT.md §9 "Under-13 drift"]. |

## FERPA / COPPA / SOPIPA position

The tool receives no student data and therefore is not a "school official" under FERPA, creates no "education records," and is not an "operator" collecting personal information under COPPA. The only data we ever hold is what adult teachers voluntarily send us about themselves. Districts that require a Data Privacy Agreement can use the SDPC national template; we will sign one that says "no data" if a district needs the paper [PRODUCT.md §8.5; privacy.a4l.org/national-dpa].

Two additions for specific jurisdictions:

- **COPPA, amended rule (compliance date April 22, 2026).** The amended definition of personal information reaches persistent identifiers used beyond internal operations. We set no persistent identifier of any kind, so no exception has to be argued [PRODUCT.md §6.2].
- **California SOPIPA (Bus. & Prof. Code §22584) and CDE guidance.** SOPIPA restricts what operators of K–12 online services may do with student information (targeted advertising, profiling, sale). We collect no student information, so none of those activities can occur. CDE's rule that "Personally identifiable information (PII) should only ever be entered into closed AI systems" is satisfied structurally: there is no path by which anything typed into this page reaches any system, open or closed [cde.ca.gov/ci/pl/aiincalifornia.asp, quoted in PRODUCT.md §2.2].

## The safety statement — read it exactly as written

We do not describe this tool as "safe," and we do not describe its output as "filtered." Here is what is true:

- The model is trained **only on synthetic children's stories** (the TinyStories dataset: stories generated by GPT-3.5 and GPT-4 using a small vocabulary; see the Model card). Its vocabulary of habit is bedtime-story English.
- The model can **in principle** emit any of the 50,257 tokens in the GPT-2 vocabulary, because no output filter sits between the probability distribution and the screen. The training distribution makes off-register output improbable; it does not make it impossible. Someone, someday, will find an odd completion [PRODUCT.md §9 row 2].
- In classroom mode, sampling is capped: temperature at most 1.5, continuations short (30 tokens or fewer), and the optional larger model is not linked from any classroom page (built — the phase-1 classroom-mode configuration in `src/classroom/config.ts`; PRODUCT.md §9, §4.1 rule 4).
- **Blocklist option.** If a district requires it, a token blocklist applied at sampling time — tokens removed from the candidate list before the dice are rolled — is a one-day change, and we will ship it as an opt-in configuration. It would still not make the model "filtered" in the sense a hosted chatbot's moderation layer is, and we would still not use the word.
- The source is public. "Trained only on synthetic children's stories, runs offline, and here is the source" is the entire claim.
- Students are not conversing with the model. They type one sentence, watch it being processed, and judge the result. Every module ends with the student evaluating the model's output against their own knowledge [PRODUCT.md §4.1 rule 5].

## Network-tab audit (for the reviewer, or for a curious student — 5 minutes)

1. Open Chrome (or Edge). Press `Ctrl`+`Shift`+`J` (macOS: `Cmd`+`Option`+`J`). Click the **Network** tab. Tick **Preserve log** and **Disable cache**.
2. Load the lesson URL. Wait for the model-loading indicator to reach 100 %.
3. Read the request list. You should see only: the HTML page, its script and stylesheet bundles, `tokenizer.json` / `tokenizer_config.json` (GPT-2 vocabulary), `tinystories-1m.safetensors` (7.5 MB) and `meta.json` — all from the lesson domain, under `/tokenizers/gpt2/` and `/weights/`. No request to any other host.
4. Clear the list (the 🚫 icon). Type a sentence into a widget; drag the temperature slider; press the dice button several times.
5. The list stays empty. That is the whole audit: student input produces zero network traffic.
6. Optional: **Application** tab → **Storage**. Cookies: none. Local storage: one key (`itm-lang`) holding `en` or `zh`. Cache storage: the model and tokenizer files.
