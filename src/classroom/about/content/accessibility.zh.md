# 无障碍声明

*《机器内部·课堂版》共享前置文档 · 草稿 2026-08-22;2026-08-23 按第四阶段无障碍检查修订。本声明随每个版本更新;"已知缺口"一节在每次审计之后填写。*

## 目标

课堂版的每个页面和每个交互件都以 **WCAG 2.1 AA 级**(Web Content Accessibility Guidelines,网页内容无障碍指南)符合性为目标。这是美国 ADA 第二章对公立 K–12 学校和社区学院网页内容(包括放进学习管理系统的课程内容)的要求,合规期限为 2027 年 4 月 26 日(服务人口 5 万以上的机构)和 2028 年 4 月 26 日(更小的机构),以司法部延期后的日期为准[PRODUCT.md §6.3;ada.gov/resources/web-rule-first-steps;jacksonlewis.com 关于 DOJ 延期的报道——引用前请确认现行日期]。过了这两个日期,不达标的资源公立学校就没法采用,所以我们把它当作硬性要求,不是锦上添花。

**截至 2026-08-23 的符合性状态:部分符合——依据是一次自动化审计加一次键盘走查;尚未用辅助技术实测。** 做了什么:(1)用 axe-core 4.13.0 对每个课堂页面做了自动化 WCAG 2.1 A/AA 审计(`npm run audit:a11y`)——首页、两个课页(刚打开时,以及把每条提示、每个小标签、掷骰、单步、表格都操作过一遍之后)、每个模块一条步骤直达链接、两份指南、两份打印页、幻灯片和七个前置文档页——英文与中文各一遍,1280 px 与 375 px 各一遍;起初发现 24 处严重或致命级问题(128 个节点:没有名字的文本框和滑块、浅色主题两处对比度不足、键盘够不到的滚动框),最终归 **零**。(2)用真实按键事件对五个交互件的每个控件做了键盘走查(记录见 REVIEW-CLASSROOM-4.md)。**没做**什么:没有用 ChromeVox、VoiceOver 或 NVDA 测试——自动化工具检查的是名称、角色、对比度和结构,它说不出读屏软件实际会念什么;没人听过之前,我们不声称知道。这一条是"已知缺口"的第一行。

## 我们按什么设计

**键盘。** 每个交互件都能不用鼠标操作;每个页面开头有一条"跳到课程内容"链接,浅色主题下每个控件都有 3 px 的焦点框(2026-08-23 用真实按键事件验证,不是靠目测):

- 在切词机和 Tokenizer X-ray 里,碎片不是 Tab 停靠点——碎片上没有任何可做的操作,所以没有什么可"操作"——但它们组成一个有名字的列表,读作"第 2 块:‘raw’,编号 1831";字母行读作一句话("strawberry:10 个字母,r 在第 3、8、9 位");小标签暴露按下状态;计数行和结论行是 polite live region。
- 在 Gamble 里,文本框有名字,温度(temperature)滑块响应方向键并播报"T = 1.10";概率条是一个有名字的列表("‘the’:41.2%");"掷骰"是按钮,掷出的词是 polite live region。
- 在 TheLoop 里,写、单步、重置都是按钮(一次运行最多 30 个 token;没有暂停控件)。每个写出的词本身是一个按钮,名字带着文字和概率("‘ sat’,61%");Enter 或空格打开鼠标悬停才能看到的候选弹层,Escape 关闭;一个 polite live region 报告"已写 12 个词;最后一个是‘ sat’,概率 61%";下方的逐步记录(见下)把每个数字都写成文本。
- 在百次掷骰(M2 的新交互件)里,触发器是按钮,滑块有名字并播报数值,摘要是 polite live region,直方图有表格替代。
- 在 AttentionRoom(M3,规划中)里,方向键在热力图单元格之间移动,层滑块和 head 选择器是标准表单控件。

**每个可视化都有文本替代**[PRODUCT.md §6.3]:

- 概率条 → 一个有名字的列表("‘the’:41.2%");条形本身作为装饰对辅助技术隐藏。已构建。
- 自回归动画 → "查看逐步记录"展开后的逐步记录:每个写出的词一行,带概率和模型权衡过的候选。2026-08-23 构建。
- 百次掷骰直方图 → "改看表格"展开后的一张表(词、模型概率、期望次数、落点次数、占比);已构建,不可排序。
- attention(注意力)热力图 → 可排序的文本表("token X 最关注 token Y,0.61")——随 M3 规划。

**不只靠颜色。** TheLoop 的置信度着色附带数值标签;自动发现的 attention head 类型附带文字标签,不只是色相。

**对比度。** 浅色与深色主题下文本对比度目标 ≥ 4.5:1。课堂页面使用一套选定前就算过对比度的浅色配色(构建第二阶段:正文 17:1,次要文字 8.6:1,灰色文字 5.9:1,链接 8.3:1);长文保持深色。2026-08-23 对两个课页和对照表的每个文本节点实算验证:审计发现两处不达标——幕号在强调色药丸上的深色字(2.3:1)和 75% 不透明度的 token 编号(在橙色底上低于 4.5:1)——现为 8.3:1 与 8.0:1;余下最低的是 X-ray 里高亮的字母,4.7:1。*禁用*控件里的文字(如第一次掷骰前的"重置",2.4:1)按 1.4.3 豁免,也是课堂页面上唯一低于 4.5:1 的文字。

**动效。** 页面尊重 `prefers-reduced-motion`(2026-08-23 模拟该偏好验证)。已构建:百次掷骰一次落地,不再播放动画;TheLoop 的"写"也一次落地——30 个词在 120 ms 内全部出现,没有闪烁光标,没有逐词停顿(开着停顿时要 4.3 s)——"单步"仍是一按一个词;跳转链接不再平滑滚动。没有任何内容自动播放。

**读屏软件。** 目标测试矩阵:ChromeVox(ChromeOS)、VoiceOver(macOS / iPadOS)、NVDA(Windows)——**三者都还没有跑过**("已知缺口"第一行)。交互件的状态变化已接到 polite live region 上;读屏软件实际会念出什么,还没有人听过。

**文本转语音。** 目标、尚未构建(见"已知缺口"):提示文字通过浏览器内置的 `speechSynthesis` 朗读,不联系任何外部服务。这是社区学院教师的明确要求[PRODUCT.md §3;arxiv.org/abs/2511.05363]。

**语言。** 页面声明自己的语言(`lang="en"` 或 `lang="zh"`),两个版本是对等文档,辅助技术会用正确的语音朗读。另一种语言的段落会自己声明(WCAG 3.1.2):中文前置文档页上每个英文的段落、列表项、引文和表格单元格——政策原文、标准编号、来信包正文——都带 `lang="en"`;英文指南标出了中文词汇表那一列和中文剪纸条。

**视频。** MVP 不含视频;将来若有视频,一律配字幕和文字稿。

**打印。** 每个模块都有打印样式表和可打印 PDF,不插电活动本身就是纸质的,所以用不了交互件的学生依然有这节课。

**缩放与重排。** 交互件自适应布局,应在 200% 缩放和 320 px 宽的视口下重排,页面不出现横向滚动。

## 已知缺口

*2026-08-23 按第四阶段检查(MVP 第 5 项)填写。原来列在这里的三条第一、二阶段构建记录缺口——X-ray 逐字母朗读的那一行、TheLoop 只能悬停的弹层、TheLoop 缺少的减少动态模式——已经关闭,见上文。剩下的是这次检查做不到的事。每条缺口按"交互件 · WCAG 成功准则 · 描述 · 变通办法 · 目标版本"记录。*

| 交互件 | 准则 | 缺口 | 变通办法 | 目标版本 |
|---|---|---|---|---|
| 每个页面和交互件 | 4.1.2 名称、角色、值;4.1.3 状态消息(实际体验) | 尚未用 ChromeVox、VoiceOver 或 NVDA 测试。名称、角色、live region 和键盘路径已由 axe-core 和真实按键事件验证;读屏软件会念什么、live region 是太吵还是太安静,还没有人听过。 | 视力正常的键盘用户不需要变通;读屏用户应预期措辞上的粗糙,而不是缺控件 | 教师试点之前(取决于作者) |
| 每个课页 | ——(教师的要求,不是 WCAG 准则) | 提示词没有朗读功能 | 用浏览器或系统自带的朗读(ChromeVox、VoiceOver、Edge 大声朗读) | MVP 之后 |
| TheLoop(M2) | 1.3.1 信息与关系 | 候选弹层能用键盘打开,但它位于那个词的按钮内部,所以读屏软件听到的是这个词的名字和概率,而不是八个候选 | 交互件下方的逐步记录表列出每个候选及其百分比 | 不计划改——逐步记录就是设计好的路径 |
| 每个页面 | 1.4.10 重排 | 重排在 375 px 下检查过(页面不横向滚动;宽表格在可聚焦的框内滚动);320 px 和 200% 缩放没有实测 | 宽表格和嵌入代码已经在各自的框内滚动 | Chromebook / iPad 设备测试(取决于硬件) |

从设计而非测试中可以预见的:attention 热力图(M3,不在 MVP 内)是最难的一个,它的键盘路径和文本表还没做[PRODUCT.md §10.2 后续项]。
